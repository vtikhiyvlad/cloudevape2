# CloudVape ↔ Эвотор: интеграция продаж

## Что добавлено

- Чтение документов SELL/PAYBACK из API Облака Эвотор v2.
- Импорт SELL в существующие Sale / SaleItem / StockMovement.
- Защита от повторного импорта по уникальной паре магазин Эвотора + ID документа.
- Сопоставление по сохранённой карте product_id Эвотора или по уникальному штрихкоду.
- Документы с неизвестными товарами сохраняются как needs_mapping без списания.
- PAYBACK сохраняется как review без автоматического изменения остатка, пока не будет
  проверена связь с исходной продажей.
- Административные endpoints для ручного запуска, сопоставления и просмотра статусов.

## Настройка

1. Получить подходящий токен/разрешения API Облака Эвотор для чтения документов.
2. В секреты окружения backend добавить:
   `EVOTOR_TOKEN=...`
3. Пересобрать/перезапустить backend.
4. Убедиться, что товары CloudVape имеют корректные штрихкоды. Если в документе
   нет штрихкода, создать mapping через `POST /api/evotor/mapping`.
5. В Swagger авторизоваться токеном CloudVape и выполнить ручной запуск:

```json
POST /api/evotor/sync
{
  "evotor_store_id": "ID-магазина-из-облака-Эвотор",
  "cloudvape_store_id": 1,
  "since_ms": 1792886400000
}
```

`since_ms` — Unix timestamp в миллисекундах. Начните с короткого периода и тестового
магазина; не импортируйте всю историю в рабочие остатки до сверки.

## Endpoints

- `POST /api/evotor/sync` — ручной импорт документов за период.
- `POST /api/evotor/mapping` — привязка ID товара Эвотора к variant_id CloudVape.
- `GET /api/evotor/documents/{cloudvape_store_id}` — журнал последних импортированных документов.
  Фильтр: `?status=needs_mapping`, `?status=review` или `?status=error`.

## Важные ограничения первого этапа

- Модуль не запускает фоновую синхронизацию сам: сначала проверяется ручной импорт.
- PAYBACK не списывает/возвращает остатки автоматически; требуется отдельная логика
  возврата и связь с исходным документом.
- Количество поддерживается только целое, так как текущие остатки CloudVape имеют тип Integer.
  Дробные позиции отправляются на ручную проверку.
- Неизвестные/неоднозначные позиции не меняют остатки.
- После первичной загрузки нужно сверить количество документов и остатков с Эвотором.
- Установить токен только в секреты сервера, никогда не коммитить его в репозиторий.
